[#DEC-020, item, role=decision, status=accepted, title="Enforce requirement atomicity at authoring and review, not in validation"]
--
Context:: Approved requirements stated several obligations each, and the conformance reviewer had to return one verdict per item. The inherited guidance already stated the rule, but only per block, and no authoring or review surface applied it.

Candidates::
* Restate the rule per item in the guidance and reference it from the authoring skills.
** Good: catches the defect where the requirement is written; cheap; the "and" exception stays a judgement call.
** Bad: advisory — the authoring agent must apply it, and approved offenders need supersession.
* A validation rule counting SHALLs per item.
** Good: automatic and always-on; catches every future offender.
** Bad: structural only, so "and" joining aspects of one outcome cannot be distinguished from two obligations; flags approved items that legitimately join one outcome; moves enforcement away from authoring.
* A dedicated atomicity review skill.
** Good: an independent check with judgement.
** Bad: another skill and step for a one-bullet problem; the conformance reviewer already reads every addressed requirement.

Decision:: Restate the rule per item in the requirement guidance, reference it from the authoring skills, and add an atomicity check to the shipped conformance reviewer. Keep "and" joining aspects of one observable outcome as an explicit exception. Add no validation rule.

Rationale:: Atomicity is semantic at the edges, so the structural check would trade precision for automation. The conformance reviewer already reads each addressed requirement and needs one verdict per item, so a multi-obligation item is a defect there for free. Authoring-time guidance prevents the next occurrence; the cold review catches what slips through.

Consequences:: The four superseded offenders are replaced by atomic successors. Earlier approved items that carried several SHALLs — REQ-005, REQ-006, REQ-028, REQ-029, REQ-038, REQ-050, REQ-052, REQ-053, REQ-054, and the REQ-066/067/068 diagram trio — were grandfathered at the time of this decision; CHG-021 has since superseded all twelve with atomic successors. Reviewers flag multi-obligation items as ambiguous verdicts and must exempt single-outcome "and" joins. If approved offenders keep appearing, revisit a validation warning.

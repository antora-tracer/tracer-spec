[#REQ-016, item, role=requirement, level=component, status=draft, title="Read the existing feature ticket"]
--
WHEN an item has an `externalId` that identifies an existing supported ticket, the system SHALL read that ticket when tracker information is requested.

[#REQ-018, item, role=requirement, level=component, status=draft, title="Keep ticket-owned state outside the graph"]
--
The system SHALL treat the external ticket as authoritative for its backlog placement, status, and estimate.

tracer:links[]

[#REQ-019, item, role=requirement, level=component, status=draft, title="Do not write or pull ticket state and estimates"]
--
The system SHALL NOT change a feature ticket's status, backlog placement, or estimate, or pull those values into graph state. Tracker interaction is limited to reading the existing ticket and, after user approval, updating its unique `TSPEC refinement` description section.

[#REQ-121, item, role=requirement, level=component, status=approved, title="Keep tracker credentials out of the repository and command text"]
--
The system SHALL read tracker credentials only from the process environment or the user's existing credential store, never from project files, command arguments, or generated output.

Example: Given `FORGEJO_TOKEN` is set, when `tspec-track` reads a ticket, then the token appears in no project file, no command line, and no printed output.

tracer:links[]
--

[#REQ-122, item, role=requirement, level=component, status=approved, title="Reject a tracker URL that carries credentials or is not HTTPS"]
--
IF a tracker URL contains embedded credentials, a query, or a fragment, or uses a scheme other than HTTPS on a non-loopback host, THEN the system SHALL reject it with a nonzero exit and a diagnostic naming the offending part.

tracer:links[]

[#REQ-056, item, role=requirement, level=software, status=approved, title="Expose the CLI as tspec when installed"]
--
WHEN the workflow CLI package is installed, the system SHALL expose a `tspec` executable that provides the existing `init` and `status` subcommands.

Example: Given the package is installed from the project repository, when the user runs `tspec --help`, the command exits successfully and lists `init` and `status`.

[#REQ-071, item, role=requirement, level=software, status=approved, title="Install workflow files for the selected harnesses"]
--
WHEN the user runs `tspec install`, the system SHALL install the workflow skills, slash commands, and agent definitions for the selected harnesses.

Example: Given a project initialized with `--tools oh-my-pi`, when `tspec install --tools oh-my-pi` runs, the skills, slash commands, and agent definition are refreshed in that harness's directories.

refines:REQ-070[]
tracer:links[]

[#REQ-072, item, role=requirement, level=software, status=approved, title="Install writes no scaffold file, even with force"]
--
IF `tspec install` runs, THEN the system SHALL NOT write or overwrite any scaffold file, including when `--force` is set.

Example: Given an initialized project whose `traceability.yml` and `docs/` were edited, when `tspec install --tools oh-my-pi --force` runs, `traceability.yml` and `docs/` are byte-identical afterwards.

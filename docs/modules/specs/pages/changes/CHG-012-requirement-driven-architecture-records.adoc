[#CHG-012, item, role=change, status=refined, trackerId=2, title="Trace architecture elements and change designs"]
--
Rationale:: ADRs preserve consequential choices but do not describe the system's architecture or a change's technical design.
The workflow needs traceable architectural elements and a durable design record for each implementation change.

Outcome:: Add an `architecture` role for independently meaningful architectural elements, classified by kind and organized in an arc42-aligned baseline.
Add a durable `design` item for each refined change, linked to the change, relevant requirements, affected architecture items, and ADRs.
Create the design before implementation tasks; update the architecture baseline to reflect the implemented system while retaining change-design and decision history.
Keep costly-to-reverse architecture choices in ADRs and domain or business choices in `DEC` items.
Update the traceability configuration, templates, guidance, and workflow skills to support these items.

Out-of-scope:: Creating a graph item for every arc42 heading or explanatory paragraph.
Duplicating requirements or decisions in architecture items.
Reclassifying domain or business decisions as ADRs.
Automatically extracting architecture items from source code.

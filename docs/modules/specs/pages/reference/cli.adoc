= CLI Reference

This page documents every command and option of the Tracer Spec Workflow CLI.
The traceability model itself is the `antora-tracer` CLI, covered for the commands the workflow uses.

== tracer-spec

`tracer-spec` scaffolds a project and installs the workflow skills.
It ships two commands.

=== init

Initialize a Tracer Spec Workflow project in the current directory.

[source,bash]
----
tracer-spec init [name] [options]
----

[cols="30a,70a"]
|===
| Argument | Description

| `name` | Project name, also used as the Antora component name and site title.
Defaults to the current directory name.
|===

[cols="25a,75a"]
|===
| Option | Description

| `--force` | Overwrite existing files instead of skipping them.
With `--link`, it replaces existing harness skill files with symlinks without writing through them.

| `--skip-skills` | Do not install the workflow skills into any harness.
Installs nothing, regardless of `--tools`.

| `--link` | Install harness `SKILL.md` files as symlinks to the package's `skills/` sources instead of copies.
Run the CLI from a repository checkout to link to working-tree files; a globally installed CLI links to its installed package.

| `--scope <scope>` | Select `project` or `user` skill installation.
When omitted in a terminal, prompts with `project` selected; without a TTY, defaults to `project`.
This option only changes skill destinations; scaffolding and slash commands remain project-local.

| `--dry-run` | Preview actions without writing any file.
Prints the component name, title, selected harnesses, and every file that would be created.

| `--tools <ids>` | Agent harnesses to install skills for: a comma-separated list, `all`, or `none`.
When omitted and the terminal is interactive, shows a picker; when not a terminal, defaults to `oh-my-pi,claude,agents`.
|===

==== Harnesses

[width=100%, cols="20a,20a,30a,30a"]
|===
| ID | Label | Project skill directory | User skill directory

| `oh-my-pi` | Oh My Pi | `.omp/skills` | `~/.omp/agent/skills`
| `claude` | Claude Code | `.claude/skills` | `~/.claude/skills`
| `codex` | Codex | `.agents/skills` | `~/.agents/skills`
| `pi` | Pi | `.pi/skills` | `~/.agents/skills`
| `agents` | Shared .agents | `.agents/skills` | `~/.agents/skills`
|===

`omp` is an alias for `oh-my-pi`.
`codex` and `agents` share `.agents/skills` at project scope; `codex`, `pi`, and `agents` share `~/.agents/skills` at user scope.

Slash commands are installed only for harnesses that define a command convention: Oh My Pi (`.omp/commands/tspec-<id>.md`) and Claude Code (`.claude/commands/tspec/<id>.md`).
Codex, Pi, and the shared `.agents` directory install skills only.
Slash commands remain project-local for either skill installation scope.

=== status

Report the lifecycle and derived readiness of one change. Run from a Tracer Spec project root.

[source,bash]
----
tracer-spec status <change-id> [options]
----

[cols="25a,75a"]
|===
| Option | Description

| `-c, --config <path>` | Traceability configuration file. Defaults to `traceability.yml`.
| `--docs <path>` | AsciiDoc source directory. Defaults to `docs/`.
|===

Both paths resolve independently relative to the command's current working directory. When running outside the project root, pass both paths.

The command reads the selected configuration and AsciiDoc source paths and prints one line containing only the change ID, its stored lifecycle status, and `actionable` and `finished` results. It never writes graph or task files or contacts a tracker.

A leaf is actionable when its status is `refined` or `accepted`; it is finished only when `closed`. A closed or rejected parent is not actionable. An unclosed parent is actionable when every child linked through `refines:CHG-parent[]` is actionable; this is evaluated recursively. Any cycle in change refinement links, duplicate item IDs in the scanned graph, or an ID that does not resolve to a change exit nonzero with an error and no status line.

== antora-tracer

`antora-tracer` is the graph engine behind the workflow.
The workflow uses these commands directly.

[cols="30a,70a"]
|===
| Command | Purpose

| `validate -i docs --config traceability.yml` | Check roles, relations, statuses, and the acceptance gate.
| `next-id --prefix CHG -i docs` | Return the next unused ID for a role prefix.
| `role-guidance <role> --config traceability.yml --content` | Print a role's item template and prefix, resolved from `traceability.yml`.
|===

The full `antora-tracer` CLI is documented in its own reference; this workflow depends on it as `@antora-tracer/core`.
== Skill evaluation

`npm run eval:skills --` runs one skill's scenario suite with Claude Code.
Each scenario runs once with the skill and once with skill commands disabled, against separate copies of the same fixture.

[source,bash]
----
npm run eval:skills -- --skill <name> [options]
----

Options:

`--skill <name>` is required and names a directory under `skills/` containing `SKILL.md`.
`--scenario <file>` selects an evaluation suite; the default is `skills/<name>/evals/evals.json`.
`--output <dir>` selects the report directory; the default is `eval-results/<name>-<timestamp>/`.
`--model <id>` selects the Claude model; the default is the CLI-configured model.
`--claude <executable>` selects the Claude Code executable; the default is `claude` on `PATH`.

The report contains per-run transcripts, standard error, workspace-change summaries, deterministic expectation evidence, execution durations, model metadata, and aggregate JSON and Markdown summaries.
The fixture directories must be trusted: the runner is not a security sandbox and does not prevent external side effects.

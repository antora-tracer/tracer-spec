= Getting Started

== Use this as a template

Tracer Spec Workflow is a reference implementation and template for spec-driven development on Antora Tracer.

== 1. Clone or fork the template

[source,bash]
----
git clone https://github.com/antora-tracer/tracer-spec.git my-project
cd my-project
npm install
----

== 2. Validate the example

[source,bash]
----
antora-tracer validate -i docs --config traceability.yml
----

Should see: `No validation errors found`.

== 3. Customize the project

Update the pages under `docs/modules/specs/pages/`:

* `use-cases.adoc` — product actors, goals, and observable flows.
* `requirements.adoc` — product, component, and software-level requirements.
* `changes.adoc` — independently deliverable implementation slices.
* `decisions.adoc` — durable domain and specification decisions.

The existing feature ticket stays authoritative for estimate and backlog state.
Related graph items may carry the optional shared `externalId` when linked to the same external item; local changes need no external ID.

== 4. Use the workflow

For feature work, refine the existing ticket into use cases and product/component requirements, then record one or more independently deliverable changes. Local changes without an external ticket can also be recorded when applicable approved graph requirements already exist.
Refine each change into testable software requirements and a task checklist before accepting and applying it.

[source,bash]
----
pi tspec-explore "Add user authentication"           # sketch product intent
pi tspec-refine-feature AUTH-001                      # feature ticket -> use cases and requirements
pi tspec-new-change "Improve saved filters"         # one implementation slice
pi tspec-refine-change CHG-001                        # software requirements and tasks
# review, then accept
pi tspec-apply-change CHG-001                         # implement tasks
pi tspec-archive CHG-001                              # verify and close
pi tspec-validate                                     # check the graph
----

== 5. Build and publish

[source,bash]
----
npm run build
----

Generates `build/site/` with the traceability matrices and coverage reports.

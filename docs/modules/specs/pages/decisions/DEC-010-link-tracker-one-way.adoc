[#DEC-010, item, role=decision, status=proposed, title="Keep ticket state external and limit writes to approved summaries"]
--
Context:: The external ticket owns its estimate, backlog placement, and status. Refinement needs a limited way to publish a summary without taking over ticket workflow state.

Options::
* Synchronize graph lifecycle or estimates with tracker state.
** Good: values could appear aligned automatically.
** Bad: introduces competing ownership and may change user-managed ticket state.
* Read tracker-owned values as external and write only a user-approved refinement summary.
** Good: leaves ticket workflow ownership with the user while providing a controlled description update.
** Bad: summary publication requires explicit user approval and does not synchronize state.

Decision:: Treat ticket backlog placement, status, and estimate as external authoritative values; never write them. After user approval, update only the unique `TSPEC refinement` section of the existing description, preserving all other content.

Rationale:: External ticket management remains user-owned. A scoped, approved summary update supports refinement without silently changing the fields the tracker owns.

Consequences:: `tspec-track` may read the existing ticket and may update its unique `TSPEC refinement` section after user approval (GitHub heading or equivalent Jira ADF section); it does not create/import tickets or synchronize status, backlog placement, or estimates. If the section is not unique, no update is made.

[#DEC-009, item, role=decision, status=proposed, title="Use shared external feature-ticket metadata"]
--
Context:: Canonical graph items need to reference an existing externally owned feature ticket without making that ticket part of graph traceability.

Options::
* Put a tracker identifier on a change only.
** Good: narrow and simple.
** Bad: use cases and requirements cannot share a canonical feature-ticket reference, and independent changes cannot explicitly refer to the same ticket.
* Use one shared `featureTicketId` scalar metadata field on canonical graph items.
** Good: use cases, requirements, and changes can point to the same external ticket; the link adds no graph relation.
** Bad: the reference is intentionally outside graph validation and traceability matrices.

Decision:: Use shared `featureTicketId` scalar metadata on canonical graph items; treat the referenced ticket as external, not as a graph item or relation.

Rationale:: One feature ticket can cover multiple independent changes and connect the feature's graph items without confusing tracker ownership with spec traceability.

Consequences:: Many items MAY share a feature ticket ID. The workflow preserves unknown legacy `trackerId` metadata and does not auto-convert it.

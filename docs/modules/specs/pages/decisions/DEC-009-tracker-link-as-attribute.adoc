[#DEC-009, item, role=decision, status=proposed, title="Use optional shared external-item metadata"]
--
Context:: Canonical graph items need to reference an existing externally owned feature ticket without making that ticket part of graph traceability.

Options::
* Put a tracker identifier on a change only.
** Good: narrow and simple.
** Bad: use cases and requirements cannot share a canonical feature-ticket reference, and independent changes cannot explicitly refer to the same ticket.
* Use optional `externalId` scalar metadata on canonical graph items associated with the same external item.
** Good: use cases, requirements, and changes can share an external identifier without adding a graph relation; local work can omit it.
** Bad: the reference is intentionally outside graph validation and traceability matrices.

Decision:: Use optional shared `externalId` scalar metadata on canonical graph items; treat the referenced external item as metadata, not a graph item or relation.

Rationale:: One external ticket can cover multiple graph items and independent changes. Local changes can omit the identifier without weakening traceability, which remains in graph relations.

Consequences:: Related items MAY share an `externalId`. The reference remains outside graph validation and traceability matrices. Preserve unknown legacy `trackerId` metadata; do not auto-convert it.

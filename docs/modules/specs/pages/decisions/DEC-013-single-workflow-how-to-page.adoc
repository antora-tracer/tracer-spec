[#DEC-013, item, role=decision, status=proposed, title="One how-to page for the nine-skill workflow"]
--
Context:: Each skill could have its own how-to page, or the workflow could be documented as one task. The workflow has nine skills across feature refinement, implementation-change refinement, ticket access, and execution.

Options::
* One combined page, “How to drive the workflow.”
** Good: the phases form one learning path, from feature intent through independent implementation changes.
** Bad: the page may grow as individual skills gain standalone procedures.
* Nine per-skill pages.
** Good: strict task separation.
** Bad: fragments the workflow sequence and repeats setup context.

Decision:: Keep one workflow how-to; split a skill into its own page only when it gains genuinely standalone steps.

Rationale:: The workflow sequence remains the main user task; the skills reference carries per-skill details.

Consequences:: The how-to documents the nine-skill sequence; the reference catalog lists each skill's arguments and operations.

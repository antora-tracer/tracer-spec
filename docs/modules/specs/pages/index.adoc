= Tracer Spec Workflow

Spec-driven development built on Antora Tracer.

This project eats its own dog food: changes, requirements, and decisions are traceable items in this very site.

== Overview

Antora-tracer/core provides projects with the ability to create traced items, like use cases, requirements, designs, or tests.
tspec builds on this and provides a spec driven development flow.
From idea, over change, to requirements and design, implementation, verification and consolidation.

=== Durable artifacts

It will create durable artifacts.

* *Changes* — the entry point: rationale, outcome, and scope, with a lifecycle from proposed to closed.
* *Requirements* — the spec unit: observable obligations a change addresses.
* *Design* – this details how changes are technically delivered.

=== Temporary artifacts

* *Tasks* — Markdown checklists under `tspec/<change-id>/`, deleted when the change closes.

=== The workflow

[source,text]
----
explore → propose → apply → archive
----

The graph is the source of truth.
Git and pull requests provide review, authorization, and change history.
A human acceptance gate plus validation enforces review before implementation.

=== Customizability

antora-tspec and antora-tracer are both customizable to your project situation.
This is driven by config files and role guidance files.
Because tspec sits on top of tracer configuration must be compatible.
Don't worry, this can be checked programmatically.

== Duality

To work with `tspec` you must know that `tspec` consists of two parts

* CLI commands
* Agent skills

You can use both.
But most likely, you are most of the time working inside your agent harness.

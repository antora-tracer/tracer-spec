= How to Scaffold a Project

This guide turns an empty directory into a Tracer Spec Workflow project with a self-tracing Antora site.

== 1. Install the CLI

[source,bash]
----
npm install -g git+https://github.com/antora-tracer/tracer-spec.git
----

The CLI needs Node.js 20+.

== 2. Initialize the project

[source,bash]
----
cd my-project
tspec init "My Project"
npm install
----

`init` writes the scaffold into the current directory:

* `traceability.yml` — the traceability model (roles, relations, matrices, workflow).
* `tspec.yml` — the tracer-spec configuration (issue-tracker bridge).
* `docs/` — the Antora content source and site.
* `antora-playbook.yml` — the site build playbook.
* `AGENTS.md` — the project's agent instructions.
* `skills/` — a local copy of the nine workflow skills.

Omit the name to use the current directory name.

== 3. Pick the agent harnesses

`init` installs the workflow skills into your agent harness directories.
By default it installs into Oh My Pi, Claude Code, and the shared `.agents` directory.

Pass `--tools` to choose:

[source,bash]
----
tspec init --tools oh-my-pi,claude   # pick specific harnesses
tspec init --tools all               # every supported harness
tspec init --tools none              # scaffold only, no skills
tspec init --tools omp,codex,pi      # omp aliases oh-my-pi
----

When you omit `--tools` and run interactively, `init` shows a picker.
When `stdin` is not a terminal, it falls back to the default set.
Pass `--scope user` to install skills for all projects, or `--scope project` for the current repository.
Omitting `--scope` prompts in an interactive terminal and defaults to project scope otherwise.
The scope applies only to skills; project scaffolding and slash commands stay local.
Use `--link` when developing skills to make harness `SKILL.md` files symlinks to the package source.
Run the CLI from a checkout to follow working-tree edits; use `--force` to replace existing skill files.
`--force` also overwrites existing scaffold files, so avoid it in a populated project unless intended.

Every harness reads the same `SKILL.md` files; only the target directory differs.
See xref:reference/cli.adoc[CLI reference] for the full flag list.

== 4. Confirm the result

[source,bash]
----
antora-tracer validate -i docs --config traceability.yml
----

Expected: `No validation errors found`.

== 5. Build the site

[source,bash]
----
npm run build
----

The site publishes to `build/site/` with the traceability matrices and coverage reports.

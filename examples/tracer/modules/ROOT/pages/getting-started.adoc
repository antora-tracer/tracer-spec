= Getting Started

== Use this as a template

Tracer Spec Workflow is a reference implementation and template for spec-driven development on Antora Tracer.

You can use it for any project:
- Web applications
- Libraries and frameworks
- Infrastructure and DevOps
- Medical or safety-critical systems
- Any domain where traceability matters

=== 1. Clone or fork the template

[source,bash]
----
git clone https://github.com/rattermeyer/tracer-spec.git my-project
cd my-project
npm install
----

=== 2. Validate the example

Before changing anything, verify the example graph is valid:

[source,bash]
----
node /path/to/antora-tracer/lib/src/cli.js validate -i docs --config traceability.yml
----

Should see: `No validation errors found`

=== 3. Customize the project

Update the top-level documents:

[source,asciidoc]
----
docs/
  use-cases.adoc     # Your user stories and stakeholder goals
  requirements.adoc  # Observable system obligations
  changes.adoc       # Features, fixes, enhancements
  adrs.adoc          # Architectural decisions
  design.adoc        # Stable architectural knowledge
----

Edit `traceability.yml` if you need:
- Additional item roles
- Custom relationships
- Different workflow states
- Domain-specific validation rules

=== 4. Use the workflow

For each change, use the Agent Skills to maintain the graph:

[source,bash]
----
pi explore-change "Add user authentication"
# Creates CHG-001

pi write-use-case CHG-001
# Creates UC-001: User logs in

pi write-requirement CHG-001
# Creates REQ-001: System SHALL validate credentials

pi record-adr CHG-001
# Creates ADR-001: Use bcrypt for password hashing

pi review-design CHG-001
# Links to DES-001: Authentication design

pi plan-change CHG-001
# Creates plans/CHG-001.plan.adoc with tasks

pi validate-traceability
# Checks for missing relationships and coverage
----

=== 5. Review and merge

Use Git pull requests for review and authorization.
No separate workflow database or transition enforcement.

Once merged, the change and its traceability are part of the durable project knowledge.

=== 6. Build and publish

[source,bash]
----
npm run build
----

Generates `build/site/` with:
- Published requirement and design documents
- Traceability matrices
- Coverage reports
- Full change history in the source repo

== Key principles

* **Single knowledge base** — Not a parallel hierarchy. One source of truth.
* **Durable artifacts** — Use cases, requirements, ADRs, design concepts live in `docs/`.
* **Temporary guidance** — Plans in `plans/` are working documents, not traceability items.
* **Git is history** — Pull requests provide review, authorization, and change tracking.
* **Declarative workflow** — Status and relationships documented; enforcement is optional.
